# 0.1.5 — 2026-10-07

## Added

- **Optional logging configuration** — document `LOG_TOOL_FAILURE_PAYLOADS`, its byte cap, signal-specific OTLP endpoints, and opt-in OTLP log export.

## Changed

- **Framework error handling** — safe integers sent to string inputs are repaired before validation; rejected arguments receive path-first hints, and tool errors carry generated request IDs.
- **Declared recovery hints** — remove redundant forwarding from Guardian handlers and service errors; framework contract filling supplies the existing hints.
- **Fetch errors** — framework messages redact URL paths and query strings, and error envelopes omit framework-added `rootCause`.
- **Docker** — run build and production dependency installs on the native build platform, cross-install for amd64/arm64, install OpenTelemetry peers at framework ranges, and prune musl-only packages from the glibc runtime.
- **README and plugin descriptions** — clarify the existing 2,000-word article-body cap across all article tools and direct readers to `web_url` for complete articles.
- **Development tooling** — sync framework scripts and skills, validate release tag annotations, strengthen definition/packaging checks, and scan CodeQL separately by language.
- **Package exclusions** — keep built MCPB files out of npm, omit idea docs and logs from bundles, and exclude env files and registry tokens from Docker contexts.

## Fixed

- **Startup configuration** — validate `GUARDIAN_API_KEY` during setup so an absent key fails startup.
- **Registry launch metadata** — launch npm entries through `npx`, remove npm-script arguments, and fix the HTTP entry's `MCP_TRANSPORT_TYPE` to `http`.
