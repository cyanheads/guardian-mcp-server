# 0.1.4 — 2026-09-21

## Added

- **Error-envelope test coverage** — `tests/mcp-server/tools/definitions/error-envelope.test.ts` drives all three tools through argument rejections, handler-thrown reasons, and service-thrown reasons, asserting both `structuredContent.error` and `content[]` text. ([#7])
- **HTTP session-mode integration test** — boots the server over HTTP and reads the resolved mode off `/.well-known/mcp.json`, covering the declared default and the `MCP_SESSION_MODE` precedence rules. ([#9])

## Changed

- **HTTP sessions default to stateless** — `createApp({ sessionMode: 'stateless' })` in `src/index.ts` makes every launch path stateless by default; the Docker image already pinned it. An exported `MCP_SESSION_MODE` still overrides it, and an empty or unsubstituted `${…}` value falls through to `stateless`. ([#9])
- **Framework `^0.13.6`** — argument rejections return a `-32602` envelope carrying `data.reason: "invalid_arguments"` and a recovery hint naming the accepted keys or missing fields ([mcp-ts-core#377], [mcp-ts-core#445]); an undeclared key whose case-folded form names exactly one declared key is rewritten before validation, e.g. `pageSize` → `page_size` ([mcp-ts-core#452]); tool error `content[]` text ends with `(reason <reason>)` plus a ` · retryable`/` · not retryable` marker where the contract declares it ([mcp-ts-core#458]); an upstream 500 is classified `ServiceUnavailable` and retried like the other 5xx statuses ([mcp-ts-core#323]); the `/.well-known/mcp.json` server card publishes the resolved session mode under `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]` ([mcp-ts-core#387]); service-raised error-contract entries carry `thrownBy: 'service'` ([mcp-ts-core#462]).
- **Framework skill tree moved to `framework-skills/`** — Claude Code and Codex auto-load a plugin's root `skills/`, so a server shipping `.claude-plugin/`/`.codex-plugin/` handed these development skills to every installing agent ([mcp-ts-core#428]). `scripts/*.ts`, `devcheck.config.json`, `.mcpbignore`, and `.env.example` re-synced from the 0.13.x scaffold.
- **README restructured** around a capability reference (per-tool error reasons, enrichment notices) with a new `MCP_SESSION_MODE` config row.
- Repo hygiene: `.github/workflows/codeql.yml` added (the one CI file every server carries); issue templates gain a security-advisory contact link, a `cyanheads` assignee, and server/framework routing guidance; `.gitignore`'s `data/` pattern anchored to the repo root; `test` script runs `vitest` directly instead of through `bunx`; `audit:fix` script added.
- Bun engines floor `>=1.3.0` → `>=1.4.0`.

## Fixed

- **`stripHtml()` decodes each entity reference exactly once** — the previous decoder ran one replacement per entity in sequence, so the `&` produced by decoding `&amp;` was decoded again by a later replacement, turning an escaped `&amp;lt;` into `<` instead of `&lt;`. Hexadecimal (`&#x2019;`) and astral-plane numeric references now decode; out-of-range code points stay literal. Resolves the CodeQL `js/double-escaping` alert. ([#10])
- **Install manifests deliver `GUARDIAN_API_KEY`** — `manifest.json` referenced the unsubstituted `${GUARDIAN_API_KEY}` and `.claude-plugin/plugin.json` wrote an empty `env` value, so the key collected at install never reached the server. Both now reference `${user_config.GUARDIAN_API_KEY}` behind a sensitive, required `userConfig`/`user_config` option; `.codex-plugin/mcp.json` forwards the host variable via `env_vars`.
